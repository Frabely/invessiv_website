         WHERE table_name='lead_call_contacts' AND column_name='project_scope';
     Muss 'YES' liefern. Sonst manuell:
         ALTER TABLE lead_call_contacts ALTER COLUMN project_scope DROP NOT NULL;

IN DIESER SITZUNG BEHOBEN
================================================================
1. origin war im discovery-call-Schema Pflichtfeld ohne Default
   -> jeder Aufruf ohne origin bekam HTTP 400. Default ergänzt wie beim
      quick-contact-Schema.
2. Natives Radio blieb beim Abwählen des Leistungsmodells checked
   -> Screenreader meldeten weiter "ausgewählt". Radio ist jetzt kontrolliert.
3. Chip-Hover ohne Pointer-Guard
   -> blieb auf Touch nach dem Tap kleben und sah aus wie "ausgewählt".
      Jetzt neutral (kein CTA-Blau) und auf @media (hover: hover) begrenzt.
4. Honeypot war beim Zusammenlegen der Formulare verlorengegangen
   -> wieder eingebaut, bricht beide Absende-Wege still ab.
5. Consent-Fehler-Id war hartkodiert
   -> kollidierte bei zwei Formularen auf einer Seite. Jetzt aus useId().
6. mapQuickContactFormToDto setzte origin nicht
   -> Mail-Anfragen von der Landingpage wären als "website" im CRM gelandet.
7. Toter Code entfernt: map-final-cta-form-to-dto.ts, final-cta-form-values
   (Contract + Default), map-final-cta-form-to-dto-options.ts sowie die
   verwaisten Copy-Keys fields.website, errorWebsite, payloadContext.
8. LandingFinalCtaFormCopy verlangte ein website-Feld, das im JSON fehlte —
   die "as"-Casts der Dictionary-Fabrik verdeckten das vor dem Compiler.
9. Zwei gelöschte Testdateien ersetzt: Honeypot- und Consent-Id-Abdeckung in
   contact-form.test.tsx, dazu ein schlanker landing-page.test.tsx, der
   Struktur statt Copy prüft (der alte pinnte ~40 Copy-Strings fest).
